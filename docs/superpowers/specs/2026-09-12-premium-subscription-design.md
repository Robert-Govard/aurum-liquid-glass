# Платная подписка (Free / Premium) — дизайн

**Дата:** 2026-09-12
**Статус:** на утверждение

## Контекст

Moneta сейчас — self-hosted приложение, в котором у всех зарегистрированных
пользователей на любом инстансе одинаковый полный доступ, без какой-либо
тарификации. Владелец инстанса `robertaurum.mooo.com` хочет монетизировать
свой собственный хостинг: люди по-прежнему регистрируются на его сервере
бесплатно, но часть функций и лимиты доступны только по платной подписке
(Premium), которую владелец включает/выключает вручную через уже
существующую админ-панель.

Это НЕ про изменение лицензии самого кода (PolyForm Noncommercial, «personal
use free forever» для тех, кто разворачивает Moneta у себя, остаётся
неизменным) — это про бизнес-модель одного конкретного хостинга поверх
уже открытого кода, аналогично тому, как GitLab/Ghost/Plausible держат
open-core продукт и одновременно продают подписку на свой собственный
managed-хостинг.

## Global Constraints

- Оплата **не автоматизирована** в этой итерации: нет интеграции с платёжной
  системой, нет вебхуков, нет напоминаний об оплате. Администратор сам решает,
  когда включить/выключить Premium конкретному пользователю, и сам собирает
  деньги любым удобным способом (существующая донат-ссылка, перевод и т.д.)
  вне приложения.
- Все 6 существующих пользователей при выкатке этой фичи переводятся на
  Free — никто не наследует Premium автоматически, администратор сам решает
  по каждому вручную.
- Администраторы (`User.is_admin`) всегда эффективно Premium, без выдачи
  через обычный механизм — `is_admin` уже существует и достаточен, отдельного
  флага не заводим.
- При истечении/отключении Premium данные **никогда не удаляются и не
  скрываются** — то, что уже создано сверх нового лимита, остаётся видимым
  и редактируемым; блокируется только СОЗДАНИЕ нового сверх лимита и доступ
  к полностью premium-функциям (Crypto/Advice/CSV-импорт/ROI).
- Экспорт/бэкап данных остаётся бесплатным без ограничений на любом тарифе —
  это про владение своими данными, тут лимит противоречил бы всей публичной
  позиции продукта («твои данные всегда твои»).
- Разделы Crypto/Совет(advice)/ROI остаются видимыми в меню на Free-тарифе
  (со значком-замочком), а не скрываются полностью — это осознанный выбор
  для того, чтобы бесплатный пользователь видел, что фича существует.
- Каждая новая строка текста на фронте — через `lib/i18n.ts` (`ru`/`en`,
  синхронно), как и весь остальной текст в проекте.

## Тарифы

### Free (по умолчанию всем)

Без ограничений:
- Дашборд, Транзакции, Категории (в пределах лимита), Бюджет, Cash Flow,
  Цели, Настройки, Регулярные платежи (в пределах лимита), финансовые
  предупреждения (`insights_service` — банер алертов на Дашборде/Net
  Worth/Бюджете остаётся частью бесплатного «ядра», это НЕ то же самое,
  что premium-раздел «Советы»/`advice_service` — их нельзя перепутать при
  реализации)
- Экспорт/импорт бэкапа — без ограничений

С числовыми лимитами:
- Счета (`Account`, неархивные): до **3**
- Активы (`Asset`, Net Worth): до **2**
- Свои категории (`Category.is_default == False`): до **5**
  (стандартные 17 сид-категорий в лимит не входят и есть у всех всегда)
- Регулярные платежи (`RecurringTransaction.is_active == True`): до **5**

Полностью недоступно (виден пункт меню, но контент — экран-заглушка
«это Premium»):
- Crypto-портфель (весь раздел `/crypto`)
- Советы (`/advice`, отдельная страница-рекомендации — НЕ банер
  предупреждений на Дашборде)
- ROI-калькулятор (`/roi`)
- Импорт транзакций из CSV (`POST /transactions/bulk`)

### Premium (включается вручную администратором на срок или бессрочно)

Все перечисленные лимиты сняты, все perечисленные разделы полностью
доступны. Ничего сверх этого — тариф не меняет поведение остальной части
приложения.

## Архитектура

### 1. Модель: поле на `User`

```python
# NULL = free (никогда не было Premium, или Premium закончился/снят).
# Дата в будущем = Premium активен до этой даты. Для бессрочной выдачи
# администратор ставит дату далеко в будущем (например, +100 лет) —
# отдельного флага "бессрочно" не заводим, чтобы не дублировать источник
# истины (см. is_premium() ниже).
premium_until: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
```

Миграция: простая nullable-колонка без бэкфилла (аналог `last_login_at`) —
все существующие пользователи получают `NULL`, то есть Free, что и
требуется по Global Constraints.

### 2. Единая точка проверки тарифа

Новый файл `backend/app/services/plan_service.py`:

```python
FREE_ACCOUNT_LIMIT = 3
FREE_ASSET_LIMIT = 2
FREE_CUSTOM_CATEGORY_LIMIT = 5
FREE_RECURRING_LIMIT = 5


def is_premium(user: User) -> bool:
    """Admins are always effectively premium — is_admin already exists and
    is sufficient, no separate override flag needed. Otherwise premium_until
    must be set and still in the future."""
    if user.is_admin:
        return True
    return user.premium_until is not None and user.premium_until > datetime.now(timezone.utc)
```

Плюс счётчики для каждого лимита (например,
`async def count_accounts(session, user_id) -> int`) — по одному на
Account/Asset/Category/RecurringTransaction, каждый с уже установленным
в проекте фильтром (неархивные счета, `is_default == False` категории,
`is_active == True` регулярные платежи).

### 3. Полное закрытие Crypto/Advice/CSV-импорта

Новая зависимость в `backend/app/api/deps.py`, по образцу уже
существующего `get_current_admin`:

```python
async def get_premium_user(current_user: User = Depends(get_current_user)) -> User:
    if not is_premium(current_user):
        raise HTTPException(status_code=402, detail="Premium subscription required")
    return current_user
```

Используется:
- `backend/app/api/routes/crypto.py` — на уровне всего роутера
  (`APIRouter(..., dependencies=[Depends(get_premium_user)])`), весь раздел
  целиком за одной проверкой.
- `backend/app/api/routes/advice.py` — так же, на уровне роутера (в файле
  всего один эндпоинт).
- `backend/app/api/routes/transactions.py` — точечно, только у
  `POST /transactions/bulk` (CSV-импорт), остальные транзакционные ручки
  этого файла остаются бесплатными.

`ROI`-калькулятор на фронте **не имеет backend-ручки вообще** — это чистая
арифметика в браузере (`RoiPage.tsx`), серверу нечего проверять. Его
premium-гейт — исключительно на фронте (см. ниже); это единственный из
четырёх premium-разделов, который технически может обойти пользователь,
открыв консоль браузера — честно фиксируем это как принятое ограничение,
не пытаясь городить фиктивную серверную проверку ради несуществующего
запроса.

Код ответа — **402 Payment Required**, не 403: в проекте 403 уже занят
другим смыслом («ты аутентифицирован, но у тебя нет прав» — не админ,
email не подтверждён). 402 — отдельный, семантически точный сигнал
именно «нужна платная подписка», который фронт отличает от обычных ошибок
и рисует экран апсейла, а не техническую ошибку.

### 4. Числовые лимиты при создании

В каждом из четырёх мест создания (`accounts.py`/`account_service.py`,
`assets.py`, `categories.py`, `recurring.py` — в том слое, где уже лежит
остальная бизнес-логика создания соответствующей сущности, без
искусственного создания новых service-файлов там, где их сейчас нет)
добавляется проверка перед вставкой:

```python
if not is_premium(current_user):
    count = await count_accounts(session, current_user.id)
    if count >= FREE_ACCOUNT_LIMIT:
        raise HTTPException(status_code=402, detail="Free plan account limit reached")
```

(аналогично для активов/категорий/регулярных платежей со своими
константами). Существующие сверх лимита записи никогда не блокируются на
чтение/изменение/удаление — лимит проверяется только в момент создания
НОВОЙ записи.

### 5. Админ-панель

- `AdminUserRead` (схема) получает `premium_until: datetime | None`.
- Новый роут `PATCH /admin/users/{user_id}/premium`, тело
  `{"premium_until": "2027-01-01T00:00:00Z"}` или `{"premium_until": null}`
  (снять Premium) — по аналогии с уже существующими
  `update_user_route`/`delete_user_route`, с той же самозащитой
  (администратор не может понижать/повышать себя через эту ручку —
  впрочем, для него это не имеет эффекта, `is_admin` и так даёт Premium).
- Фронт: в списке пользователей (`AdminUserList.tsx`) — метка тарифа
  (Free / Premium до `<дата>` / Premium навсегда, если `premium_until` дальше
  чем 10 лет от текущего момента) и способ задать/снять дату (поле даты +
  кнопка «выдать навсегда», которая просто подставляет дату +100 лет — без
  отдельного UI-состояния «бессрочно», это только вопрос отображения
  конкретной уже сохранённой даты).

### 6. Фронтенд: что видит обычный пользователь

- `CurrentUser` (`lib/auth.ts`) получает поле `is_premium: boolean` —
  вычисленное на бэкенде (тем же `is_premium()`) и отдаваемое в `/auth/me`,
  чтобы фронт не дублировал логику дат/is_admin у себя.
- Пункты меню Crypto/Советы/ROI остаются в навигации всегда, получают
  небольшой значок-замочек, когда `!currentUser.is_premium`.
- При переходе на любую из этих трёх страниц без Premium — вместо обычного
  содержимого рендерится общий переиспользуемый компонент-заглушка
  («Это часть Premium» + короткое объяснение, без формы оплаты — оплата вне
  приложения) вместо того, чтобы дать реальному запросу на бэкенд упасть с
  402 и показать пользователю сырую ошибку.
- При достижении лимита счетов/активов/категорий/регулярных платежей —
  кнопка/форма добавления показывает то же сообщение вместо создания (по
  тому же принципу: не давать 402 всплыть как случайная ошибка).
- Импорт CSV (`CsvImportPage.tsx`) для не-Premium показывает то же
  сообщение вместо формы загрузки файла.

## Тестирование

- Backend: `is_premium()` — админ всегда True независимо от
  `premium_until`; `premium_until` в будущем/прошлом/`NULL`; ровно на
  границе (`premium_until == now` — считается истёкшим, `>`, не `>=`).
- По одному тесту на лимит (создание N успешных + N+1-я с 402 на Free,
  N+1-я успешна на Premium) для счетов/активов/категорий/регулярных
  платежей.
- По одному тесту на каждый из трёх backend-defended разделов (Crypto,
  Advice, CSV-импорт): 402 на Free, 200/201 на Premium.
- Тест админ-роута: выдача/снятие `premium_until`, включая то, что
  запрос без прав администратора получает уже существующий 403 (не эта
  фича — существующий `get_current_admin` гейт).
- Frontend: как и весь фронтенд в проекте — `npm run build`, без тестового
  фреймворка; визуальную проверку значков-замочков и экранов-заглушек
  нужно сделать самостоятельно.

## Вне скоупа (явно)

- Любая автоматизация оплаты (платёжный шлюз, вебхуки, автопродление,
  неудачные списания, счета/инвойсы) — администратор управляет тарифом
  вручную.
- Email-уведомления об истечении/скором истечении Premium.
- Промежуточные тарифы (например, "Plus" между Free и Premium) — только
  два уровня.
- Скидки/промокоды/пробный период.
- Изменение самой лицензии кода Moneta — это только про бизнес-модель
  одного хостинга.
